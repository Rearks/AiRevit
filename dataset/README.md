# AiRevit Dataset — Руководство по разметке

## Структура папок

```
dataset/
├─ pdf/                    ← Исходные PDF-файлы планов
│  └─ plan_001.pdf
├─ images/                 ← PNG-рендеры страниц (опционально)
│  └─ plan_001_page_1.png
├─ annotations/            ← JSON-аннотации (по одному на страницу)
│  ├─ _template.json       ← Пустой шаблон — копируйте для нового плана
│  ├─ plan_example_office.json  ← Пример заполненного файла
│  └─ plan_001_page_1.json
├─ schema.json             ← JSON Schema для валидации
└─ README.md               ← Этот файл
```

## Как добавить новый план

### Шаг 1. Положите PDF
Скопируйте ваш PDF в `dataset/pdf/`, например `plan_001.pdf`.

### Шаг 2. (Опционально) Сделайте скриншот страницы
Сохраните PNG-рендер нужной страницы в `dataset/images/`, например `plan_001_page_1.png`.
Это поможет при визуальной проверке аннотации.

### Шаг 3. Скопируйте шаблон
```
dataset/annotations/_template.json → dataset/annotations/plan_001_page_1.json
```

### Шаг 4. Заполните аннотацию
Откройте JSON и заполните поля. Ниже — инструкция по каждому разделу.

## Как заполнять

### `source` — откуда данные
```json
{
  "pdf_file": "plan_001.pdf",
  "page": 1,
  "image_file": "plan_001_page_1.png",
  "pdf_type": "vector"
}
```
- `pdf_type`: `"vector"` если PDF родной (из AutoCAD/Revit), `"scan"` если скан бумаги

### `metadata` — общая информация о плане
```json
{
  "building_type": "office",
  "floor_number": 2,
  "scale": "1:100",
  "total_area_m2": 127.5,
  "annotator": "ваше_имя",
  "annotation_date": "2026-04-03",
  "quality": "high"
}
```

Допустимые `building_type`:
| Значение | Описание |
|----------|----------|
| `residential` | Жильё (квартиры, дома) |
| `office` | Офис |
| `public` | Общественное здание |
| `industrial` | Промышленное |
| `medical` | Медицинское |
| `educational` | Образовательное |
| `mixed` | Смешанное |
| `other` | Другое |

### `rooms` — список помещений

Для **каждого** помещения на плане создайте запись:

```json
{
  "id": "r1",
  "kind": "kitchen",
  "name": "Кухня",
  "room_number": "101",
  "width_mm": 3000,
  "length_mm": 4000,
  "height_mm": 3000,
  "area_m2": 12.0,
  "has_window": true,
  "window_count": 1,
  "is_wet_zone": true,
  "confidence": 1.0
}
```

#### Правила для `id`
- Должен быть **уникальным** внутри файла
- Используйте осмысленные имена: `corridor_1`, `office_1`, `wc_1`, `kitchen_1`
- Или простые: `r1`, `r2`, `r3`

#### Допустимые `kind`
| Значение | Описание | `is_wet_zone` |
|----------|----------|---------------|
| `office` | Кабинет, офис | нет |
| `corridor` | Коридор, холл прохода | нет |
| `meeting` | Переговорная, конференц-зал | нет |
| `wc` | Санузел, туалет, душевая | **да** |
| `kitchen` | Кухня, кухня-столовая | **да** |
| `lobby` | Лобби, вестибюль, приёмная | нет |
| `room` | Комната (универсальное) | нет |
| `storage` | Кладовая, серверная, подсобное | нет |
| `dining` | Столовая, обеденная | нет |
| `bedroom` | Спальня | нет |
| `living` | Гостиная, общая комната | нет |
| `hallway` | Прихожая, тамбур | нет |
| `staircase` | Лестничная клетка | нет |
| `elevator` | Лифтовой холл | нет |
| `balcony` | Балкон | нет |
| `loggia` | Лоджия | нет |
| `technical` | Техническое помещение | зависит |
| `server_room` | Серверная | нет |
| `reception` | Ресепшн | нет |
| `wardrobe` | Гардероб | нет |
| `laundry` | Прачечная | **да** |
| `other` | Другое | зависит |

#### Как определять размеры
- Берите размеры **с чертежа** (если указаны размерные линии)
- Если размеров нет — оцените по масштабу
- `width_mm` — **короткая** сторона
- `length_mm` — **длинная** сторона
- Если помещение неправильной формы — запишите примерные размеры вписанного прямоугольника
- `polygon_mm` — можно оставить пустым, заполнять только если легко определить координаты

#### `confidence`
- `1.0` — точно уверены в типе и размерах
- `0.8` — почти уверены, но есть нюансы
- `0.5` — угадали тип по контексту
- `0.3` — не уверены

### `doors` — двери и проёмы

```json
{
  "id": "d1",
  "between": ["corridor_1", "office_1"],
  "width_mm": 900,
  "door_type": "single"
}
```

- `between` — два `id` помещений, которые соединяет дверь
- `door_type`: `"single"`, `"double"`, `"sliding"`, `"opening"` (проём без двери)
- Стандартные ширины: 700 (подсобные), 800 (санузлы), 900 (жилые/офисные), 1200 (двустворчатые)

### `edges` — граф связей

**Это самая важная часть для машинного обучения!**

Для каждой пары помещений, которые связаны, добавьте edge:

```json
{
  "source": "corridor_1",
  "target": "office_1",
  "type": "connected_by_door",
  "shared_wall_mm": 3500
}
```

#### Типы связей
| Тип | Описание | Когда использовать |
|-----|----------|-------------------|
| `adjacent` | Общая стена (без двери) | Соседние комнаты через глухую стену |
| `connected_by_door` | Есть дверь между ними | Самый частый тип |
| `connected_by_opening` | Проём без двери / арка | Кухня-столовая без двери |
| `near` | Рядом, но нет общей стены | Через коридор, по диагонали |

#### Правила заполнения edges
1. **Всегда** добавляйте `connected_by_door` если есть дверь
2. **Всегда** добавляйте `adjacent` если есть общая стена без двери
3. `shared_wall_mm` — длина общего участка стены (приблизительно)
4. Порядок `source`/`target` не важен
5. Не дублируйте: если пара уже есть, не добавляйте в обратном порядке

### `statistics` — итоговая статистика

Эту секцию можно заполнять в последнюю очередь. Просто посчитайте:

```json
{
  "room_count": 9,
  "door_count": 8,
  "total_area_m2": 130.0,
  "corridor_ratio": 0.24,
  "avg_room_area_m2": 14.4,
  "max_room_area_m2": 31.5,
  "min_room_area_m2": 3.0
}
```

- `corridor_ratio` = суммарная площадь коридоров / общая площадь

## Чеклист перед коммитом

- [ ] `source.pdf_file` совпадает с именем файла в `pdf/`
- [ ] Все `id` в `rooms` уникальны
- [ ] Все `between` в `doors` ссылаются на существующие `id`
- [ ] Все `source`/`target` в `edges` ссылаются на существующие `id`
- [ ] Для каждой двери есть соответствующий edge типа `connected_by_door`
- [ ] `kind` — только из разрешённого списка
- [ ] `width_mm` и `length_mm` > 0
- [ ] `statistics.room_count` совпадает с количеством элементов в `rooms`

## Паттерны для проверки (будущая статистика)

Когда наберётся 50+ аннотаций, можно будет проверить гипотезы:

1. **Кухня → Столовая**: как часто `kitchen` соседствует с `dining`?
2. **Столовая > Кухня**: площадь `dining` обычно больше `kitchen`?
3. **Коридор = хаб**: степень узла `corridor` обычно >= 3?
4. **Санузлы вместе**: `wc` часто `adjacent` друг к другу?
5. **Кладовая = лист**: `storage` обычно имеет degree = 1?
6. **Окна**: какие помещения обычно имеют окна?
