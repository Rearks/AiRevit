# План реализации проекта AiRevit (Генерация BIM по тексту)

## Концепция
Основываясь на подходе итеративной генерации геометрии агентом (представленном в концепции CLAUDE.md для других проектов), наша цель — создать агента, который переводит текстовый запрос в параметры или готовый код, а затем автоматически генерирует элементы внутри САПР (Revit).

## Задача 1 (Базовая): Смоделировать гипсокартонную стену длиной 1000 мм по текстовому запросу.

### Требуемые инструменты и технологии
1. **Интерфейс в Revit:** Dynamo (например, Python Node на CPython 3) или pyRevit (написание прямых плагинов на Python для вызова из ленты). Для старта Dynamo — наиболее простой вариант.
2. **LLM (Мозг):** API OpenAI (GPT-4o) или Anthropic (Claude 3.5 Sonnet).
3. **Фреймворк агента:** На первом этапе достаточно прямых REST API вызовов (с функцией Structured Output типа JSON). Для более сложных задач и многошаговых размышлений можно использовать фреймворки (LangChain, LangGraph, smolagents, Nanobot, Openclaw).
4. **Бэкенд (Опционально):** Для простоты можно запускать код локально внутри Revit. Для продакшена и безопасности API-ключей потребуется бессерверное облако (Google Cloud Functions, Yandex Cloud Functions, AWS Lambda), которое будет играть роль прокси между Revit и LLM.

---

### Пошаговый план реализации базовой операции:

#### Шаг 1: Разработка структуры данных (Промпт-инжиниринг)
Необходимо создать контракт взаимодействия. LLM должна возвращать строго форматированный JSON, понятный для Revit.
*Пример ожидаемого JSON:*
```json
{
  "element_type": "wall",
  "wall_type_keyword": "Гипсокартон",
  "length_mm": 1000,
  "start_point": [0, 0, 0],
  "level_name": "Уровень 1"
}
```
**Действие:** Написать "System Prompt" (Системное сообщение) для агента: *"Ты — Revit BIM ассистент. Твоя задача — извлекать параметры из текстового запроса пользователя для создания стен. Верни список параметров в формате JSON."*

#### Шаг 2: Создание скрипта-клиента для Revit (Связь с агентом)
Написать Python-скрипт (для Dynamo / pyRevit), выполняющий следующие функции:
1. Вывод диалогового окна для ввода текста (например, окно из `Data-Shapes` для Dynamo или `System.Windows.Forms`).
2. Отправка POST-запроса через встроенный в Python модуль `requests` (или `urllib`) к API мозге (OpenAI/Anthropic либо к вашему облачному вебхуку).
3. Получение и парсинг полученного JSON-кода.

#### Шаг 3: Разработка логики построения геометрии (Revit API)
Внутри того же скрипта (или с помощью нодов Dynamo), получив структурированные параметры:
1. **Поиск Уровня:** Найти `Level` по имени или взять активный на текущем виде.
2. **Поиск Типа стены:** Найти `WallType`, в имени которого содержится полученный "wall_type_keyword" (например, "Гипсокартон").
3. **Конвертация единиц:** Revit API оперирует футами. Необходимо разделить полученную длину `1000` мм на `304.8`.
4. **Создание кривой (Curve):** Создать линию от точки `(0,0,0)` до `(Length_feet, 0, 0)`.
5. **Создание стены:** Использовать метод API: `Wall.Create(document, curve, wallTypeId, levelId, height, offset, flip, structural)`.

#### Шаг 4: Тестирование базового цикла (The Loop)
1. Открываем пустой проект Revit.
2. Запускаем Dynamo скрипт. Вводим: *"Построй стену из гипсокартона длиной 1 метр"*.
3. Скрипт обращается к AI -> получает команду -> строит геометрию в Revit.
4. Проверяем корректность типа стены и её длины.

### План масштабирования (после реализации Шага 4)

Для перехода от простых стен к целым помещениям с инженерными сетями, потребуется усложнить агента:

1. **RAG (Поиск по контексту модели):** Модели в Revit имеют разные стандарты и названия семейств. До запроса к LLM нужно выгружать JSON-список названий всех загруженных типоразмеров стен, систем, оборудования. Передавать этот словарь агенту, чтобы он выбирал реально существующие внутри проекта элементы, а не "галлюцинировал" их названия.
2. **Логика расстановки (Layout Math):** Агент должен уметь выдавать массивы элементов (4 стены, соединенные друг с другом углами) и вычислять координаты их концов. 
3. **Агент-Программист (Agent-as-a-Coder):** Для сложных сетей и генерации помещений JSON контракта станет недостаточно. Агент (типа Openclaw или кастомного на LangGraph) на облачном сервере должен будет получать задачу и генерировать **прямой исполняемый Python-код для Revit API**. Revit запускает этот код с помощью `exec()`, отлавливает ошибки, отправляет логи ошибок обратно агенту, и агент исправляет код, пока помещение не построится (аналог итеративного цикла из CLAUDE.md).
